# Document families — settled

Families organise document types and help with recommendations; they regulate nothing (owner).

- A family is a value of the set `DOC_FAMILIES`, kept in Types & sets like any other list, coded as the organization
  likes. A type names its family on the type (`family`); else a code whose first letter is a family's code falls in it
  (the supplier notation, C102 in C).
- Read on Help (`/guide#families`): each family with the document types in it, and the types in none.
  `/settings/families` only redirects there.
- The outside stamp rule (NONE / BEFORE / AFTER, prop `stamp`) is gone: a stamp is a review's, and only a review's
  (CLAUDE.md, "A stamp is a review's").

## Still open

- Recommendations by family (criticality, what a type usually carries) are not built: today the document type
  recommends its own criticality. When the owner wants it, a family's recommendation would fill what a type leaves empty.
